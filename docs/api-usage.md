# Mac API 用量、费用与赠额提醒

此功能属于 `flyyangX/codex-account-switcher` fork 的本地开发版本。上游项目由刘朝（Zhao Liu，`liuzhao1225`）创建，MIT 许可与版权保留。本文示例全部为合成数据。

## 启动与连接

运行 `./scripts/package-api-monitor.sh`，打开脚本最后输出的 `Codex API Monitor.app`。实际目录由 `swift build -c release --show-bin-path` 决定（本机为 `.build/out/Products/Release/`）。这个包使用独立名称和 Bundle ID `com.flyyang.codex-api-monitor`，不安装或覆盖已有应用，不连接上游 Sparkle 更新源。API 窗口默认打开，也可从菜单栏的“API 用量与赠额”进入。

1. 点击右上角连接设置菜单中的“添加组织”，填写官方组织 ID（`org-…`）、名称和可选项目 ID（`proj_…`）。留空项目表示整个组织，包括未归属项目的费用。
2. 在概览顶部直接选择“今日、近 7 天、近 30 天、本月、上月”，或打开“自定义”使用日期选择器。日期范围包含首尾两天、按 UTC 账单日查询，最长 366 天，今日查询到刷新时刻。选择按组织保存，切换账号后会恢复。旧配置保留“已设周期”，赠额批次也可设为统计周期；非 UTC 边界的旧周期仍按完整日桶参考展示。
3. 在 [OpenAI 官方平台](https://platform.openai.com/settings/organization/admin-keys)创建有相应读取权限的专用 Admin API Key，在界面的安全输入框保存。普通项目调用 Key 和 Codex 登录凭据不能替代。每个组织只保留一份配置和一项凭据，再次保存同一 ID 会更新配置，不按 Codex 账号重复汇总。
4. 点击“刷新”。应用启动和运行时每 15 分钟刷新当前选中的组织；切换组织会刷新对应统计。网络错误不会连续重试。

只有 GET 请求会发送到固定官方域名，拒绝重定向。不会调用模型、切换 Codex 账号或修改官方组织。此独立包专注 API 窗口与独立菜单，不读取现有 Codex 凭据、不启动 Codex 配额刷新。源码中的普通 Account Switcher 构建保留原有账号操作和新增的 API 入口。

## 界面与周期

左侧切换账号和“账单概览／赠额与提醒”；顶部展示当前账号与刷新状态。概览包括所示范围费用、请求次数、Token 总量、逐日费用柱状图和模型用量条形图。费用图仅使用实际返回的 UTC 日桶，按币种切换、悬停查看精确金额，不补造缺失日期或缺失币种的零值。金额汇总仍使用 Decimal，图表绘制才转换为浮点数；多币种不会相加。

“数据明细与统计口径”保留组织／项目、实际查询范围、日桶覆盖、每项最后成功时间、精确费用及全部模型的输入／输出／缓存输入。今日费用也可在这里查看。主页突出主要信息，配置与完整说明放在次级入口。

额度栏独立显示总额度和剩余额度，带核对时间及“核对额度”入口。它是官方账单页面／邮件的核对记录，按组织保存，不随周期筛选改变，也不由 Costs 自动扣减；仅确认初始赠额时会改标“已知初始赠额”，未知余额保持待核实。月度花费上限不可填写为总额度。只有同口径的总额与剩余均已核对时才绘制剩余占比环。

周期切换会取消旧请求；加载时保留旧数据并标注，失败时各接口独立保留原范围。费用和用量的缓存范围不同会额外提示，旧缓存不会换上新周期标签。日期选择器支持取消、校验首尾顺序和最长区间。

## 同级账号登记与待绑定

账号可以先登记，再连接组织账单。账号名称只是显示标识，不按名称或邮箱推断组织；只有显式配置或官方响应可核实时才建立绑定。普通项目 Key 不能代替 Admin Key，缺少组织或管理权限的账号显示待绑定，不显示零用量或零余额。多个账号可关联同一组织，组织费用始终只查询和展示一次。账号附注可记录已核实的赠额日期和仍未知的精确时刻；附注金额不是当前余额。

## 指标与数据边界

| 显示 | 来源与含义 |
| --- | --- |
| 今日费用 | 官方 `/v1/organization/costs`，UTC 账单日当天起点至刷新时刻；在数据明细中查看 |
| 所示范围费用 | 官方 Costs，按配置区间查询并显示实际返回日桶覆盖；边界可能包含周期外时段，因此标为日桶参考。按官方币种分别求和，保留退款负数，不用 token 价格估算 |
| 请求、输入／输出 token、模型分布 | `/v1/organization/usage/completions`，覆盖 Responses／Chat Completions；缓存输入已包含在输入 token 中，不再重复相加 |
| 费用明细 | Costs 按 `project_id` 和 `line_item` 分组，包含接口返回的全部计费能力，不局限于 completions |
| API 总额度／剩余额度 | 组织账单页面的核对记录，带来源与核对时间；未知显示待核实，不声称 Admin API 自动同步 |
| 本地剩余额估算 | 首版不计算。多批赠额、混合付费、退款和缺失数据无法从总费用准确还原赠额抵扣顺序 |

主页显示当前费用数据的实际 UTC 查询范围，数据明细显示每项独立范围与最后成功刷新时间（北京时间）。起点包含、终点不包含，存储和请求以 Unix 时间为准。金额在解码、计算和存储中使用 `Decimal`，摘要金额按展示精度缩写，悬停与数据明细保留精确金额，不把极小非零金额显示为零。

Usage 与 Costs 均遍历 `has_more`／`next_page`。任一页失败、游标循环、重复桶、必要金额字段缺失或项目归属不符，整项结果不可用，不接受部分汇总。真实接口的 UTC 日桶标签会超出非 UTC 对齐的查询边界：客户端接收与查询相交的日桶，同时显示请求范围与实际日桶覆盖，保留完整金额，不按小时拆分，也不把日桶参考金额冒充精确赠额周期费用。官方返回的极端指数零值（如合成格式示例 `0E-6176`）会在 JSON 数值 token 层归一化为零，不改动非零金额或引号内字符串。

401、403、限流、服务端失败和网络错误分别显示。已有成功数据会保留原范围和时间，错误或超过 30 分钟标为过期。无成功结果时显示“未连接／待核验”。官方返回空条目时显示“未返回费用条目”，不解释为赠额余额为零。账单数据可能存在延迟。

首版不单独统计嵌入、图像、音频、工具或存储的请求量；这些能力的费用仍通过 Costs 明细展示。没有实现 Windows API 界面或修改 Windows Host 协议。

## 赠额记录与提醒

批次包含金额、币种、组织、发放时间、精确到期时间、来源和核对时间。时间输入采用带时区的 ISO 8601，例如 `2030-05-10T23:59:59+08:00`；本地存储保留绝对时间和毫秒精度，默认北京时间显示到秒。不知道精确到期时刻时应先核对官方账单，不猜测当天午夜。

有效区间为 `[发放时间, 到期时间)`，到期后不滚入下一批。“有效期内”仅指时间状态，不表示还有可用余额。批次金额和费用始终分开显示。

“赠额与提醒”中的“启用提醒”默认关闭，只有主动开启才请求 macOS 通知权限。提醒按到期时刻提前 7／3／1 个 24 小时排程；发放前和已经错过的时点不补发。稳定标识符避免重复，编辑到期时间或删除记录会重排／撤销待发送提醒。移除组织会同时清理该组织的凭据、缓存、手工批次和待发送提醒。普通“断开”仅清理凭据与账单缓存，保留手工批次及其提醒。

仅知道到期日期时，可在“赠额与提醒”点击“设置到期日期”，或右键账号登记 `YYYY-MM-DD`（Asia/Shanghai）。独立的日期提醒在提前 3 天、1 天的北京时间 09:00 触发，正文说明准确到期时刻待核实；触发时间不作为到期时刻，也不进入赠额余额计算。编辑或清除日期会重排／撤销对应待发送提醒。

最多预排最近 60 条，其余在应用运行时的后续刷新中补排。新增／修改排程和后台读取需应用运行；已经排程的本地通知交由 macOS 投递。权限、系统通知设置、专注模式、休眠与关机会影响实际显示，不保证电脑关闭时仍准时提醒。本地 ad-hoc 签名包尚未公证；本次已在用户开启后回读系统授权和待发送日期提醒，跨重启与到期实际投递仍需验收。

## 本机数据与凭据

- 配置与缓存：`~/Library/Application Support/Codex API Monitor/API Usage/`，目录 `0700`、文件 `0600`，原子替换。通知状态回读单独保存在 `notification-status.json`，仅含授权状态、请求标识与触发时间，不含密钥或通知正文。
- Admin Key：仅在本机 Keychain，独立 service `com.flyyang.codex-api-monitor.admin-key`，不参与 iCloud 同步，仅本设备解锁时可读。界面不回显已保存密钥。
- 配置、缓存、导出、日志与 Codex `auth.json` 不保存此功能的 Admin Key；本功能没有导出或诊断上传接口。
- 设置中的“断开并清理此组织密钥”删除该组织 Keychain 项与账单缓存，不代表吊销官方 Key；如需吊销，应在官方平台操作。文件删除不承诺擦除 APFS 快照或外部备份。
- 独立包的 Codex profile 目录为 `Codex API Monitor/Accounts/`。原有账号切换行为和权限边界保留；API 数据读取与其分离。

## 开发验证

```sh
swift build
swift test
./scripts/run-core-checks.sh
node scripts/check-site-geo.mjs
node --test scripts/tests/*.test.mjs
./scripts/package-api-monitor.sh
```

`--api-demo` 仅显示合成数据，阻止网络刷新、Keychain 写入、持久化和通知权限请求，便于本地界面检查。模型与客户端测试使用临时目录、内存凭据和合成 HTTP 响应，不读取真实凭据或消费额度。

测试覆盖金额／币种／退款、分页与参数归属、权限／接口／网络失败、时间边界、缓存过期和保留、批次有效期和提醒标识、重复组织、断开清理及配置不含密钥。已有三个真实组织的 Admin Key 通过 Usage／Costs GET 读取及 Mac 窗口手动刷新验证；没有发起模型生成调用。平台延迟和通知最终投递仍需分别验收；本地构建不等于生产发布或员工／客户验收。

可选的本机 Keychain 集成检查：`SWITCHER_TEST_KEYCHAIN=1 swift test --filter APIUsageModelTests`。仅创建、读取、替换和删除随机组织 ID 下的合成测试项，结束后清理，不读取已有组织密钥；默认不在 CI 或锁定钥匙串环境执行。
